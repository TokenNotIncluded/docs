## 侧边栏分组

侧边栏从上到下按六个标题分组,覆盖接入到政策的完整链路:

- **开始使用**:总览、认证与会话、API 总览。
- **API 端点**:中继 API 与管理 API 的自动生成端点页面,以及响应兼容、只读查询、图像轮询和远程控制专题。
- **部署与运维**:部署与环境、数据与缓存、运行时与诊断。
- **计费与支付**:模型价格锁、支付金额契约、CC Switch 余额、推荐奖励和开源赏金。
- **产品与功能**:产品术语、内置助手、渠道设置、OAuth 设置、前端设计与等待体验。
- **政策与法律**:用户协议、隐私政策、服务条款以及中法俄三份术语词汇表。

<Note>
  两份 OpenAPI 规范保存在 `docs/openapi/`,站内所有端点页面由它们自动生成,不需要手写。
</Note>

## 推荐阅读路径

先完成认证和端点选择,再进入部署运维。只有需要改动线上状态时,才阅读部署与运维中的发布事务页面。

<Steps>
  <Step title="认证并发出第一个请求">
    阅读[认证与会话](/docs/authentication),了解面板访问令牌和中继 API Bearer 契约。令牌必须保留在服务端,并在会话或部署发生变化时轮换。
  </Step>
  <Step title="选择兼容端点">
    进入 [API 总览](/docs/api-reference),再根据客户端选择 Chat Completions、Responses、Messages、Gemini、嵌入或媒体端点。端点页面可交互,能直接填入令牌发送请求。
  </Step>
  <Step title="在安全环境中验证">
    修改生产状态前,先完成[启动设置](/docs/setup-startup)中的检查,再阅读[CLI 部署契约](/docs/backend-cli-deployment-contract)中的验证契约。
  </Step>
  <Step title="依据证据运维">
    按需查看[服务器运维](/docs/server-ops)、数据库、诊断和部署事务页面,让每次变更都可回滚、可审计。
  </Step>
</Steps>

<Warning>
  生产变更必须遵循文档中的验证和审批步骤。演练结果、历史日志或一次成功的健康检查都不能替代当前的发布契约。
</Warning>

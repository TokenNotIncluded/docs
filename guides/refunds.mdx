The Tokenz Refunds API lets you return funds to customers for completed orders. Refunds are processed asynchronously — initiate them via the API and then monitor their progress via webhooks or by polling the refund object.

<Note>
  All monetary values use the smallest currency unit (e.g., `10000` = ¥10,000 JPY or $100.00 USD). Zero-decimal currencies such as JPY and KRW use the value as-is. See [Currencies](/guides/currencies) for details.
</Note>

## Refund statuses

| Status | Meaning |
|---|---|
| `pending` | Refund initiated and currently being processed |
| `failed` | Refund attempt failed |

## Create a refund

Send a `POST` request to `/v2/refunds` with the order ID and a reason. The refund is created immediately in `pending` status and processed asynchronously.

<CodeGroup>
```bash create-refund.sh
curl --request POST \
  --url https://api.tokenz.one/v2/refunds \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE' \
  --header 'Content-Type: application/json' \
  --data '{
    "orderId": "order_1p4LPTRKB5Z",
    "reason": "customer_cancellation",
    "detail": "Customer requested cancellation before delivery"
  }'
```

```json refund-response.json
{
  "refund": {
    "id": "refund_1p4LS47fB1h",
    "object": "refund",
    "orderId": "order_1p4LPTRKB5Z",
    "amount": { "amount": 10000, "currency": "JPY" },
    "status": "pending",
    "reason": "customer_cancellation",
    "initiatedBy": "apikey",
    "test": false,
    "createdAt": "2024-10-07T10:30:00Z"
  }
}
```
</CodeGroup>

### Request parameters

<ParamField body="orderId" type="string" required>
  The ID of the completed order you want to refund.
</ParamField>

<ParamField body="reason" type="string" required>
  The reason for the refund. Accepted values are `customer_cancellation`, `duplicate_payment`, or `other`.
</ParamField>

<ParamField body="detail" type="string">
  A free-text description of the refund reason. Required when `reason` is `other`; optional for all other reasons.
</ParamField>

## Retrieve a refund

Send a `GET` request to `/v2/refunds/{refundId}` to fetch the current state of a specific refund.

```bash get-refund.sh
curl --request GET \
  --url https://api.tokenz.one/v2/refunds/refund_1p4LS47fB1h \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE'
```

## List refunds

Send a `GET` request to `/v2/refunds` with query parameters to retrieve a paginated list of refunds.

```bash list-refunds.sh
curl --request GET \
  --url 'https://api.tokenz.one/v2/refunds?orderId=order_1p4LPTRKB5Z&limit=10' \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE'
```

### Query parameters

| Parameter | Type | Description |
|---|---|---|
| `orderId` | string | Filter refunds by order ID |
| `status` | string | Filter by refund status (`pending` or `failed`) |
| `limit` | integer | Number of results to return (1–100, default `10`) |
| `createdAfter` | string | Return refunds created after this ISO 8601 timestamp |
| `createdBefore` | string | Return refunds created before this ISO 8601 timestamp |

```json refunds-list.json
{
  "refunds": {
    "items": [ { "...refund object..." } ],
    "hasMore": false
  }
}
```

## Refund webhooks

Subscribe to refund events to update your internal records when a refund's status changes.

| Event | Trigger |
|---|---|
| `refund.created` | Refund successfully initiated |
| `refund.failed` | Refund attempt failed |

<Tip>
  Use test API keys (prefix `secret_test_`) to create test orders and then refund them in a safe sandbox environment. Test refund IDs end with `_t`, and all webhooks are delivered to your test endpoint with `"test": true` in the payload.
</Tip>

## Error codes

| Status | Code | Meaning |
|---|---|---|
| 404 | — | Order or refund not found |
| 422 | `refund.amount-exceeds-available` | Refund amount exceeds the available balance on the order |

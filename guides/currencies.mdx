Tokenz supports 45 currencies across APAC, Europe, the Americas, and beyond. All monetary amounts in the API — both in requests you send and responses you receive — use the smallest minor unit for that currency (for example, cents rather than dollars). Understanding how to convert your display amounts to API amounts is essential to avoid incorrect charges.

## How minor units work

The "minor unit" is the smallest denomination of a currency. Most currencies divide into hundredths (e.g., 1 USD = 100 cents), so you multiply your display amount by 100 before sending it to the API. Some currencies have no subdivision at all (zero-decimal), and a small number divide into thousandths (three-decimal).

| Display amount | Currency | Calculation | API value |
|---|---|---|---|
| $12.99 | USD | 12.99 × 100 | `1299` |
| ¥1,200 | JPY | 1200 × 1 (zero-decimal) | `1200` |
| 10.500 BHD | BHD | 10.500 × 1000 | `10500` |

## Zero-decimal currencies

<Note>
  The following currencies have **no minor unit** subdivision. Pass the face value directly — do **not** multiply by 100:

  **CLP, IDR, JPY, KRW, TWD, UGX, VND**

  For example, ₩5,000 KRW → send `5000`, not `500000`.
</Note>

## Three-decimal currencies

Bahraini Dinar (BHD), Kuwaiti Dinar (KWD), and Omani Rial (OMR) subdivide into 1,000 fils. Multiply your display amount by **1000** when sending values to the API.

For example, 5.250 KWD → send `5250`.

<Warning>
  API **responses** also return amounts in minor units. When displaying amounts to customers — in confirmations, receipts, or dashboards — divide the API value by the factor (e.g., divide USD by 100). For zero-decimal currencies, display the value as-is.
</Warning>

Orders are automatically created when Checkout Sessions are created. Use the Orders API to retrieve order details, cancel orders before they complete, and register delivery records for fulfillment tracking and dispute protection.

<Note>
  All monetary values use the smallest currency unit (e.g., `1200` = ¥1,200 JPY or $12.00 USD). Zero-decimal currencies such as JPY, KRW, and VND use the value as-is. See [Currencies](/guides/currencies) for the full list.
</Note>

## Order statuses

| Status | Meaning |
|---|---|
| `requiresPayment` | Awaiting customer payment |
| `processing` | Payment received; being processed |
| `succeeded` | Order completed successfully |
| `failed` | Order failed after processing |
| `blocked` | Temporarily blocked from further actions |
| `canceled` | Canceled; will not proceed |
| `expired` | Expired without completion |

## Retrieve an order

Send a `GET` request to `/v2/order/{orderId}` to fetch the full order object, including its status, line items, and timestamps.

<CodeGroup>
```bash get-order.sh
curl --request GET \
  --url https://api.tokenz.one/v2/order/order_1D5xA9BnKfv_t \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE'
```

```json order-response.json
{
  "id": "order_1D5xA9BnKfv_t",
  "object": "order",
  "status": "succeeded",
  "amount": { "amount": 3700, "currency": "JPY" },
  "items": [
    {
      "id": "item_1D6F8mR5TnK_t",
      "detail": {
        "product": {
          "price": { "amount": 1200, "currency": "JPY" },
          "quantity": 3,
          "label": "Emerald Pack"
        }
      }
    }
  ],
  "reference": "ORDER_2024_001",
  "test": true,
  "createdAt": "2024-01-15T10:00:00Z",
  "updatedAt": "2024-01-15T10:05:30Z"
}
```
</CodeGroup>

## Cancel an order

Send a `POST` request to `/v2/order/{orderId}/cancel` to cancel an order. No request body is required. On success, Tokenz returns the updated order object with `status: "canceled"` and a `canceledAt` timestamp.

```bash cancel-order.sh
curl --request POST \
  --url https://api.tokenz.one/v2/order/order_1D5xA9BnKfv_t/cancel \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE'
```

<Warning>
  You cannot cancel an order that has already reached `succeeded` status. Attempting to do so returns a `422` response with code `order.status-invalid`.
</Warning>

## Register a delivery record

Delivery records are your evidence in disputes. When a customer challenges a charge, Tokenz and the card network look for delivery records to confirm fulfillment. They are also required for auditing purposes. You can make multiple delivery calls per order to support partial fulfillment.

```bash register-delivery.sh
curl --request POST \
  --url https://api.tokenz.one/v2/order/order_1D5xA9BnKfv_t/delivery \
  --header 'Authorization: Bearer secret_test_YOUR_KEY_HERE' \
  --header 'Content-Type: application/json' \
  --data '{
    "at": "2025-01-15T10:30:00Z",
    "status": "succeeded",
    "progress": "completed",
    "user": {
      "userId": "player_98765",
      "emailAddress": "player@example.com"
    },
    "items": [
      {
        "sku": "gold-ring-350",
        "name": "Gold Ring",
        "deliveredQuantity": 2
      }
    ]
  }'
```

```json delivery-response.json
{
  "success": true,
  "message": "Delivery record has been registered successfully"
}
```

### Delivery record field guide

| Field | Importance | Description |
|---|---|---|
| `status` | Critical | `succeeded` or `failed` |
| `progress` | Critical | `completed`, `in_progress`, or `pending` |
| `at` | Critical | ISO 8601 timestamp of when delivery occurred |
| `user.userId` | Recommended | Your internal player or user identifier |
| `user.emailAddress` | Recommended | Player email address |
| `items` | Recommended | Array of delivered items with SKUs and quantities |

## Order webhook events

Subscribe to order events to drive your fulfillment logic. Do not rely on redirect URLs to trigger fulfillment — webhooks are the authoritative signal.

| Event | When |
|---|---|
| `order.created` | Order created via Checkout Session |
| `order.succeeded` | Payment completed — fulfill here |
| `order.expired` | Order expired without payment |
| `order.canceled` | Order canceled |
| `order.failed` | Order payment failed |

<Tip>
  Store order IDs in your own database as soon as you receive `order.created`. Use the `order.succeeded` webhook — not the post-payment redirect URL — to trigger fulfillment. Register delivery records promptly after fulfillment; they are your primary evidence if a dispute is opened.
</Tip>

## Error codes

| Status | Code | Meaning |
|---|---|---|
| 404 | `entity.not-found` | Order not found |
| 422 | `order.status-invalid` | Action not allowed in the current order status |

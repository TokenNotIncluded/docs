---
title: "价格锁响应一致性"
sidebarTitle: "价格锁一致性"
description: "价格锁响应与快照之间的一致性要求。"
---

Go 供应方的单模型 `PUT /api/option/` 锁定操作会在 `success`、`warnings` 和 `locked_models` 之外返回可选的 `pricing` 对象,其取值沿用既有的 JSON 编码配置格式。涉及的十一个键为 `ModelPriceLock`、`ModelPrice`、`ModelRatio`、`CompletionRatio`、`CacheRatio`、`CreateCacheRatio`、`ImageRatio`、`AudioRatio`、`AudioCompletionRatio`、`billing_setting.billing_mode` 和 `billing_setting.billing_expr`。

该快照在持有定价策略行锁的情况下直接从数据库捕获,描述的是该锁定事务所保护的定价,而不是之后可能读取到的进程陈旧缓存。只有在事务与运行时发布都成功时才会返回。普通配置项写入不会附带该快照,也不会包含无关配置项、凭据或用户记录。既有权限与锁定价格写入保护保持不变。

前端在每次写入前仍会检查实时的价格锁支持能力。当写入返回快照时,前端会校验完整的键集合、每个编码映射以及所请求模型的锁定状态,然后只替换缓存中的定价字段,并用这些被接受的值丢弃已锁定模型的草稿。提交响应到这次更新之间不会再有额外的 GET 请求,无关的查询缓存变更会被保留。

省略 `pricing` 的旧 Go / Rust 供应方继续走后续 GET 路径;该读取必须成功,仍然声明价格锁支持,并报告所请求的锁定状态。存在但格式错误的快照不能回退到可能陈旧的 GET。写入或刷新出错会使缓存的配置项失效,并且不返回成功的草稿结果:传输错误不能证明写入已经回滚。

`GET /api/option/` 也会等待完整的进程内配置项发布(包括周期性的数据库重载)结束后再复制配置项并派生 `CompletionRatioMeta`。既有的端点过滤仍会排除敏感字段。这不会把各自缓存的副本变成全局可线性化的读取服务;其他管理员仍可能提交更晚的变更。

本次源码变更不需要模式迁移、版本变更、发布或部署。已有安装需要更新后的 Go 二进制才能获得快照响应。当前端与供应方版本不一致时,保留检查过的旧路径仍是必要的。

密钥页面可以把只读的钱包余额查询导入 CC Switch。在导入对话框中,所有者必须显式启用**允许此密钥读取账户余额**。这会立即授予该密钥的所有持有者访问账户持久化钱包余额的能力。重新打开对话框并关闭即可撤销,无需再次导入。取消导入不会撤销已经做出的显式权限变更。除非确实希望披露,否则不要在共享密钥上启用该选项。

导入通过 CC Switch 的供应方深链接协议携带 `usageScript`(base64)、`usageEnabled=true`、`usageBaseUrl` 和 `usageAutoInterval=5`。脚本通过 `{{apiKey}}` 使用供应方凭据,不内嵌第二份凭据或浏览器会话。CC Switch 仍会要求用户确认导入的配置。不支持用量脚本导入的旧客户端需要升级或手动配置查询。

## API

`PUT /api/token/:id/account-balance-access` 在既有的所有者认证密钥管理 API 上接受 `{"enabled":true}` 或 `{"enabled":false}`。ID 必须属于已认证的所有者,OAuth 托管的密钥被排除。普通中继 API 密钥无法为自己授予权限。

`GET /v1/balance` 接受 `Authorization: Bearer API_KEY`,使用与 `/v1/usage` 相同的持久化密钥认证:已禁用、已过期、已删除、OAuth 托管以及受 IP 限制的密钥都会被拒绝,已禁用账户同样被拒绝。额度耗尽的密钥仍可查询余额。未获授权的密钥会收到 HTTP 403 与 `account_balance_access_required`,而不是零余额。

成功响应示例(虚构数据):

```json
{
  "valid": true,
  "scope": "account",
  "currency": "USD",
  "remaining": 23.61,
  "updated_at": 1789459200,
  "consistency": "persisted_snapshot"
}
```

`remaining` 是所有者持久化钱包额度除以 `QuotaPerUnit`,无论站点显示货币或 `DisplayTokenStatEnabled` 如何设置,始终以美元表示。零余额与负余额都会保留。订阅额度、令牌限制和累计消费不计入其中。未决的用量写入可能延迟快照,它既不是消费授权,也不构成原子计费保证。响应使用 `Cache-Control: no-store`。查询共享既有的按账户 30 次/分钟的额度查询限流;导入的客户端每五分钟刷新一次。

`/v1/usage` 仍以令牌为作用域。无限制令牌在该接口中仍返回空的剩余额度,这不代表账户余额无限制。

## 迁移与发布说明

增量迁移 `apps/api-rust/migrations/0010_account_balance_access.sql` 新增 `tokens.account_balance_read`,为非空布尔值,默认 false。已有密钥不会自动获得权限。在启用 Rust 路由之前先应用该向前迁移(或等价的 Go 模型迁移)。较早的 Go 版本会忽略这个增量列。Go 与 Rust 都会在每次余额请求时读取持久化标记,因此撤销立即生效。本次不包含生产部署或供应方归属变更。

发布说明:在所有者显式且可撤销的授权之后,密钥页面的 CC Switch 导入可以包含账户钱包余额,而不再只显示令牌用量。

本文定义钱包充值与订阅支付使用的单位。只有数字或 `$` 符号不足以表达货币类型。

## 量纲

| 名称 | 含义 | 单位 |
| --- | --- | --- |
| `platform_units`(`P`) | 计入用户的内部平台余额 | 平台单位 |
| `cny_per_usd`(`R`) | 运维人员实时配置的法币汇率 | CNY / USD |
| `platform_units_per_cny`(`B`) | 运维人员配置的钱包购买比率 | 平台单位 / CNY |
| `settlement_amount` | 发送给供应方并从中校验的金额 | 真实 ISO 法币 |
| `price_multiplier` | 分组、渠道、阶梯或优惠券调整 | 无量纲 |

`R` 与 `B` 相互独立,显示货币设置与已废弃的供应方 `unit_price` 都不能替代它们。测试中的示例汇率属于测试数据,绝不是生产常量。

## 钱包充值

对于在无量纲倍数 `M` 之前授予 `P` 个平台单位的充值:

```text
base_cny = P / B
net_cny  = base_cny * M
```

供应方结算随后是真实法币换算:

```text
Epay (CNY)           = net_cny CNY
USD provider         = net_cny / R USD
```

跳转到供应方之前,报价必须持久化以下全部信息:

- 计入的平台单位或额度;
- 以整数微单位(或供应方最小单位)表示的预期结算金额;
- 大写的 ISO 结算货币;
- 供应方、产品与店铺绑定,以及稳定的交易号;
- 已应用的无量纲倍数。

回调只有在金额、货币、供应方和产品绑定都与持久化记录匹配后才授予价值。

### 前端报价展示

钱包保留 `/api/user/topup/info` 返回的展示字段,包括 `settlement_currency`、`platform_units_per_usd`、`settlement_units_per_usd`、`settlement_units_per_platform_unit`、`max_topup` 和 `max_topup_amount`。解析时保持十进制字符串完整。这些字段描述报价的货币与换算关系;应付金额仍以既有的金额端点为准。平台入账与真实法币支付分开显示。

`max_topup` 是计入的美元上限,不是平台额度金额。Go 后端使用全局钱包汇率推导以充值请求所接受单位表示的 `max_topup_amount`,在令牌显示模式下还使用 `QuotaPerUnit`。重复的支付类型共享其中最严格的配置上限。自定义网关定价、折扣和显示货币不会改变该上限。前端只把自己的输入与 `max_topup_amount` 比较。如果旧后端省略该字段,报价与结算端点仍会执行美元上限;客户端不得自行猜测换算关系并拦下本来有效的购买。

金额、支付方式或优惠码发生变化时,未决的折扣校验与支付确认都会失效。针对较早输入的成功响应不得为当前输入授权确认。结算在服务端仍会重新计算并执行支付规则。

结算链接折扣按金额、支付方式、优惠码和当前输入修订版本校验。更换支付方式会重新校验折扣,确认会等待匹配的折扣报价。校验或报价失败会解锁优惠码以便编辑和手动重试,不进入自动重试循环。规范化有效优惠码不得触发重复校验。

首页购买入口遵循服务端的开发者准入判断。待审核账户继续进入审核流程,已批准账户可以进入钱包。注册链接会等待实时的注册能力。支付不会授予开发者权限,定价概览在批准之前不会暴露受保护的模型目录。

## 订阅计划

`SubscriptionPlan.PriceAmount` 与 `SubscriptionPlan.Currency` 共同构成真实 ISO 法币标价,它不是钱包充值金额,绝不能经过 `P / B` 换算。

旧版 0 计划虽然实际按平台额度或人民币金额运作,却被强制标记为 `USD`。启动时会将它们一次性迁移为 `CNY` 并设置 `PriceCurrencyVersion=1`;显式创建的版本 1 美元计划仍保留 USD。

对于标价 `F USD` 的计划:

```text
Epay                 = F * R CNY
Waffo/Pancake        = F USD
Stripe/Creem (USD)   = F USD
wallet balance       = F * R * B platform units
```

如果引入其他受支持的 ISO 源货币,应先把真实法币换算为真实法币,仅在钱包余额支付时再换算为平台单位。

待支付订阅订单会保存不可变的计划与权益快照、预期结算微单位金额、ISO 货币、供应方产品与价格 ID,以及供应方订阅 ID。供应方回调与续费绝不能根据可变的设置或可变的计划行重新定价。

## 续订生命周期

- 首次成功结算只创建一条本地权益。
- 每次续费支付都有供应方事件或交易的幂等键,并记录计费周期。
- 支付失败与 `past_due` 不会授予新的周期。
- 期末取消在已付费周期内保留已付费访问权。
- 立即取消或退款只依据经过校验的供应方证据和产品策略执行撤销。
- 美元与人民币合计按 ISO 货币分别汇总,绝不直接相加。

## 舍入

业务计算使用十进制算术。只在供应方边界上按该货币支持的最小单位策略舍入,并持久化回调必须匹配的精确舍入金额。

所有请求都发往同一个基础地址：

```text
https://api.lmm.best
```

中继 API 负责模型与媒体调用，规范在 `docs/openapi/relay.json`。管理 API 负责控制台操作，规范在 `docs/openapi/api.json`。每个端点的参数、响应和示例在侧边栏的 **API 参考** 中。

## 按协议鉴权

同一枚 API Key 按目标协议放入请求。

<CodeGroup>
```bash OpenAI
curl https://api.lmm.best/v1/chat/completions \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.6-sol","messages":[{"role":"user","content":"hi"}]}'
```

```bash Anthropic
curl https://api.lmm.best/v1/messages \
  -H "x-api-key: sk-xxxxxxxx" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-sonnet-4-6","max_tokens":256,"messages":[{"role":"user","content":"hi"}]}'
```

```bash Gemini
curl "https://api.lmm.best/v1beta/models/gemini-3.6-flash:generateContent" \
  -H "x-goog-api-key: sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"parts":[{"text":"hi"}]}]}'
```
</CodeGroup>

Anthropic 请求也可以使用 `Authorization: Bearer sk-...`。Claude Code 使用这种方式。Gemini 请求也接受查询参数 `?key=sk-...`。

## 查找常用端点

| 端点 | 方法 | 作用 |
| --- | --- | --- |
| `/v1/models` | GET | 列出当前 API Key 可用的模型 |
| `/v1/chat/completions` | POST | OpenAI 格式对话 |
| `/v1/responses` | POST | OpenAI Responses，供 Codex 使用 |
| `/v1/messages` | POST | Anthropic Messages，供 Claude Code 使用 |
| `/v1beta/models/{model}:generateContent` | POST | Gemini 格式 |
| `/v1/embeddings` | POST | 文本嵌入 |
| `/v1/completions` | POST | 文本补全 |
| `/v1/rerank` | POST | 重排序 |
| `/v1/moderations` | POST | 内容审核 |
| `/v1/images/generations` | POST | 图像生成 |
| `/v1/images/edits` | POST | 图像编辑 |
| `/v1/videos` | POST | 视频生成 |
| `/v1/audio/transcriptions` | POST | 语音转写 |
| `/v1/audio/speech` | POST | 语音合成 |
| `/v1/usage` | GET | 查询当前 API Key 的额度与用量 |
| `/v1/pricing` | GET | 查询模型单价 |
| `/v1/balance` | GET | 查询账户余额。API Key 需要先获得授权。 |

<Warning>
  规范中标记为未实现的 Fine-tunes 和 Files 端点尚未提供。调用会失败。集成前先确认目标端点的状态。
</Warning>

## 识别响应

中继 API 的成功响应与对应协议一致。客户端按原生 SDK 解析。

错误响应使用这个结构：

```json
{
  "error": {
    "message": "invalid api key",
    "type": "invalid_request_error"
  }
}
```

状态码见[错误与排查](/docs/troubleshooting)。

## 处理限流和超时

| 场景 | 行为 |
| --- | --- |
| 流式请求长时间没有新输出 | 连接中断。客户端自行重试。 |
| `/v1/usage`、`/v1/balance`、`/v1/pricing` | 按账户限流，每分钟 30 次。收到 `429` 时，遵守 `Retry-After` 并退避。 |
| Claude Code 的 `/compact` 等长上下文请求 | 耗时可能较长。给客户端留出足够的超时时间。 |
